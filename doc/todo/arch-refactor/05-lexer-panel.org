#+title: Lexer Panel
#+date: 2026-06-18
#+phase: 2b (after 04 — parallel with 06, 07)

Wrap the inline ~displayLex~ logic in a ~LexerPanel extends VisualizationPanel~.
The lexer panel renders source tokens as ~span.code-item~ elements, writes
~selectedStart~ to the store on click, and on selection change highlights the
selected subtree's spans + publishes its primary-span anchor.

* Background

Currently the lexer rendering and interaction live entirely in the demo:

- ~displayLex~ (demo lines ~299–319~) binds ~Lexeme[]~ to spans, sets
  ~data-start~, colors them, and on click of a meaningful token calls
  ~this.focusByStart?.(d.start)~ — i.e. it reaches directly into the AST panel.
- The reverse direction (subtree span highlight + connector) lives in
  ~onHighlight~ (demo lines ~231–268~): it walks ~collectSubtreeStarts(node)~,
  styles each matching span, marks the primary span (the one whose
  ~start === node.start~) with a border, and draws the ~ast-lexer~ connector
  from the AST rect to that primary span.

The refactor splits these: *click* writes to the store; *subtree highlight +
anchor* happens in ~onSelectionChange~.

Container: ~#lox-lexer~.  Anchor id: ~'lexer'~.

.on('click', (event, d) => {

** DONE Implement ~onSelectionChange~ (subtree highlight + primary anchor)
   :PROPERTIES:
   :files:    app/src/lox-visualizer/panels/lexer-panel.ts
   :END:

Port the span-highlighting half of ~onHighlight~ (demo 234–263):

1. Clear any previous span styling (port ~clearSpanHighlight~, demo 221–229 —
   tracks styled spans and resets ~background/border/borderRadius/padding~).
2. If ~state.selectedStart === null~: clear styling, call
   ~this.setAnchor(null)~, return.
3. Determine which spans to light up:
   - If ~state.selectedAstNode~ is set, use ~collectSubtreeStarts(node)~ (import
     from ~@/lox-visualizer/ast~) to highlight the whole subtree, bordering the
     primary span where ~start === selectedAstNode.start~.
   - Else (no node yet), highlight just the single span with
     ~data-start === selectedStart~ as the primary.
4. Find the *primary span* element; if none, clear anchor + return.
5. ~this.setAnchor(primarySpan.getBoundingClientRect())~ — this feeds the
   ~ast↔lexer~ line.  The AST panel publishes the ~'ast'~ end; the connector
   layer draws the line when both are present.

Use ~this.container.querySelector('span[data-start="N"]')~ scoped to the panel's
container rather than ~document.querySelector('#lox-lexer ...')~.

* Open questions

- *Subtree highlight before node resolves*: between the click (write
  ~selectedStart~, ~selectedAstNode: null~) and the AST panel's write-back, the
  lexer shows only the single primary span; once the node arrives it expands to
  the subtree.  That's a brief two-step flash.  Acceptable?  Alternative: the
  AST panel resolves synchronously in the *same* tick so subscribers see the
  node immediately — but ordering of subscribers then matters.  Decide in 06.
- *Whitespace lexemes*: they get ~data-start~ too but ~category === null~, so
  clicks are ignored — preserve this.
