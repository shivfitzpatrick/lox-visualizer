Make a Lox compile/runtime error an ordinary return value instead of a
JavaScript exception, and give the frontend the result code.

*This stream edits the clox repository* (~$(LOX_PROJECT)~ =
~$(HOME)/Code/learn/cs/crafting-interpreters/clox~), not this one.

* Background

~clox/src/main_wasm.c~:

#+begin_src c
  EMSCRIPTEN_KEEPALIVE
  void runSource(const char* source) {
    initVM();
    InterpretResult result = interpret(source);
    if (result == INTERPRET_COMPILE_ERROR) exit(65);
    if (result == INTERPRET_RUNTIME_ERROR) exit(70);
  }
#+end_src

The wasm build does not set ~EXIT_RUNTIME~, so the glue has
~noExitRuntime = true~ and ~exit()~ becomes:

#+begin_example
  exit → exitJS → err("program exited (with status: 70), but keepRuntimeAlive()
                       is set ...")
               → _proc_exit → quit_(code, new ExitStatus(code)) → throw
#+end_example

The exit status carried nothing the frontend read — the human-readable message
is already on stderr via ~runtimeError~ / the compiler's error reporting, and
reaches ~printErr~ *before* the throw.  So the exception is pure downside: it
makes a typo indistinguishable from a segfault at the JS boundary.

#+begin_src c
  EMSCRIPTEN_KEEPALIVE
  int runSource(const char* source) {
    initVM();
    return (int)interpret(source);   /* errors already reported on stderr */
  }
#+end_src

Leave ~src/main.c~ alone — the native CLI's exit codes (65/70/64) are the
conventional Unix behaviour and are used by the test scripts.

Check whether ~freeVM()~ should be called before returning.  ~initVM()~ runs on
every ~runSource~ call and never had a matching teardown; with ~exit()~ gone,
nothing reclaims the previous run's objects, so repeated runs leak.  If
~freeVM()~ is safe to call at the top of ~runSource~ (guarded for first use), do
it there.
