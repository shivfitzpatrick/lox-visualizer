Once program errors no longer throw (stream 02), an exception out of
~runSource~ means one thing: the module is dead.  Say so.

* Background

A trap — C stack overflow from deep Lox recursion, OOB write, failed ~malloc~ —
goes through the glue's ~abort()~, which throws ~WebAssembly.RuntimeError~ and
sets ~ABORT = true~.  After that the instance is unusable: memory is trapped and
the export wrappers' ~assert(runtimeInitialized)~ no longer holds.  Re-running
cannot work, so the Build button *should* be disabled — but deliberately and
with a reason, not stuck mid-run as today.

Depends on 02: before it, this state would fire on every typo.

* Tasks

** TODO Distinguish crashed from running
   :PROPERTIES:
   :files:    app/src/lox-visualizer/lox-visualizer.ts
   :END:

In ~reportRunFailure~, set ~this.root.dataset.crashed = ''~ — a separate flag
from ~data-running~, which stream 01's ~finally~ always clears.

Message, reader-facing first and the raw text second:

#+begin_example
  The interpreter crashed and cannot continue. Reload the page to try again.
  (WebAssembly.RuntimeError: ...)
#+end_example

Have ~runAndPublish~ bail early if ~dataset.crashed~ is already set — calling
into a dead module produces a second, more confusing failure.

Alongside the existing ~[data-running] .lox-run-button~ rule:
