The glue's ~err()~ is bound to our ~printErr~, so Emscripten's own diagnostics
are rendered to readers as error lines next to clox's messages.

* Background

~lox.js~ line ~1277~: ~if (Module['printErr']) err = Module['printErr']~.  Every
internal warning therefore lands in ~consoleStore~ via the ~stderr~ event.  A
reader who typed ~var x = ;~ currently sees clox's message followed by:

#+begin_example
  program exited (with status: 65), but keepRuntimeAlive() is set (counter=0)
  due to an async operation, so halting execution but not exiting the runtime
  or preventing further async execution (you can use emscripten_force_exit, if
  you want to force a true shutdown)
#+end_example

Stream 02 removes the trigger for that particular line, but the class of
problem remains (~checkUnflushedContent~, ~abort~ text, future glue warnings).

** TODO Build the shipped artifact without ASSERTIONS
   :PROPERTIES:
   :files:    clox/Makefile (WASM_FLAGS)

The current ~WASM_FLAGS~ set no optimisation or assertion level, so the shipped
module is an ~-O0~ ASSERTIONS build — hence the ~assert()~ calls throughout the
glue and the ~checkUnflushedContent~ machinery.  Adding ~-O2 -sASSERTIONS=0~
shrinks the artifact and removes this class of noise at the source.

Keep a debug build available for local work — a second target (~wasm-debug~)
rather than a flag flip, so the two do not get confused.

Measure the size difference and note it here; the module is served on a blog
post, so it is worth knowing.
