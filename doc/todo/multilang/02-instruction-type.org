Replace ~CompilerEvent~ in the panel/renderer data path with a neutral
~Instruction~ type.  Mapping from Lox WASM events happens only in
~deriveVizData~ (~lox-data.ts~); ~bytecode.ts~ and ~bytecode-panel.ts~ stop
importing ~events.ts~.

* Background

~CompilerEvent~ (~events.ts~) is clox-specific (~src_offset~, ~chunk~, Lox op
names).  Python ~dis.Instruction~ uses different field names but the same
logical row.  The bytecode renderer only needs offset, op, operand display, and
a source-link key (~srcOffset~).

Today:

- ~VizData.chunks~ is ~Map<string, CompilerEvent[]>~ (after *01*).
- ~drawBytecode~ and ~BytecodePanel~ import ~CompilerEvent~ directly.
- Rows use ~data-src-offset="${d.src_offset}"~ in the DOM.

* Target ~Instruction~ shape

#+begin_src typescript
export interface Instruction {
    chunk: string;
    offset: number;
    op: string;
    line: number;
    srcOffset: number;
    arg?: number;
    argCount?: number;
    constant?: string;
    jumpTarget?: number;
}
#+end_src

Field mapping from ~CompilerEvent~:

| CompilerEvent | Instruction |
|---------------+-------------|
| ~chunk~ | ~chunk~ |
| ~offset~ | ~offset~ |
| ~op~ | ~op~ |
| ~line~ | ~line~ |
| ~src_offset~ | ~srcOffset~ |
| ~arg~ | ~arg~ |
| ~arg_count~ | ~argCount~ |
| ~constant~ | ~constant~ |
| ~jump_target~ | ~jumpTarget~ |

Omit ~upvalues~ and other Lox-only fields from ~Instruction~ unless the renderer
needs them (it does not today).

export function deriveVizData(state: LoxState): VizData {
    const lexemes = state.lex();
    const ast = state.parse();
    const chunks = mapCompilerChunks(state.compile());
    return { lexemes, ast, chunks };
}
