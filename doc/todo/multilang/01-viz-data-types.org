#+title: VizData and VizSelection Types
#+date: 2026-06-18
#+phase: 1a (parallel with 03; gate for 02)

Introduce language-neutral names for the derived snapshot and cross-panel
selection.  Keep Lox-specific names as deprecated type aliases so existing
imports keep compiling during migration.

Canonical spec: [[file:design-doc.org][design-doc.org]] → "Generic data contract".

* Background

Today ~lox-data.ts~ exports ~LoxData~, ~LoxDataStore~, ~VisualizerSelection~,
and ~deriveLoxData~.  Every panel and ~visualization-panel.ts~ imports those
names.  Phase 2 will move this file to ~compiler-viz/types.ts~; Phase 1 only
renames and documents the contract *in place*.

~ConsoleStore~ and ~ConsoleMessage~ stay as-is (already generic enough).

* Target shapes (~lox-data.ts~)

** Offset convention (document now)

Add a file-level comment in ~lox-data.ts~:

- All ~selectedStart~, ~Lexeme.start~, and instruction source keys are *UTF-16
  code unit* offsets into the editor document string (JavaScript ~String~ indexing).
- Language adapters (Python, later) must flatten native spans to this convention
  before publishing ~VizData~.
