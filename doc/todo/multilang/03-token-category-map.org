#+title: Injectable Token Category Map
#+date: 2026-06-18
#+phase: 1c (parallel with 01; independent of 02)

Extract Lox token-type → highlight category mapping into an injectable
~TokenCategoryMap~ so a future Python adapter can supply its own map without
importing the Lox ~TokenType~ enum.  ~LexerPanel~ stays dumb: it renders
~Lexeme.category~ already set on each lexeme.

* Background

~TOKEN_TYPE_MAP~ in ~state/token.ts~ maps clox ~TokenType~ keys to
~TokenCategory~.  ~LoxState.lex()~ uses it via ~mapToken()~ to fill
~Lexeme.category~ before data reaches the lexer panel.

The lexer panel imports ~TokenCategory~ for styling rules (~code-keyword~ class,
clickable cursor) but does *not* import ~TOKEN_TYPE_MAP~ today.  Phase 1
prepares the *adapter boundary*:

1. Move the Lox map to a dedicated module with a neutral type.
2. Wire ~LoxState~ / ~mapToken~ through that module.
3. Export ~LOX_TOKEN_CATEGORY_MAP~ for the Lox orchestrator to pass explicitly
   when Phase 2 makes the registry shared.

* Target types (~token-map.ts~ — new file)

#+begin_src typescript
import type { TokenCategory } from '@/lox-visualizer/state/token';

/** Maps a language-specific token type key to a highlight bucket. */
export type TokenCategoryMap = Record<string, { category: TokenCategory | null }>;

/** Lox/clox token types → shared highlight categories. */
export const LOX_TOKEN_CATEGORY_MAP: TokenCategoryMap = { /* moved from TOKEN_TYPE_MAP */ };
#+end_src

~TokenCategory~ enum stays in ~token.ts~ (shared highlight buckets).  ~TokenType~
enum stays in ~token.ts~ (Lox-specific) but ~TOKEN_TYPE_MAP~ moves out.

#+begin_src typescript
import { LOX_TOKEN_CATEGORY_MAP } from '@/lox-visualizer/token-map';

function mapToken(lexerEvent: LexerEvent) {
    const type = mapTokenType(lexerEvent.type);
    return {
        type,
        start: lexerEvent.start,
        length: lexerEvent.length,
        ...LOX_TOKEN_CATEGORY_MAP[type],
    };
}
#+end_src
