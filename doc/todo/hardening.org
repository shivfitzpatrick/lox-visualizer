Goal: make the visualizer safe to demo to a stranger in the first 90 seconds,
then stop. This is a hardening pass, not a feature pass. Hard timebox: *one
week* (two absolute max). Anything tempting beyond this list goes under
[[*Future directions (README fodder — do not build)][Future directions]] as a
sentence, not a branch.

Definition of done for the whole pass: a stranger can load the page, pick an
example, click around, scrub an execution, hit an error case, and nothing
confuses or breaks — and I can explain any file in the repo without hedging.

* TODO [#A] 1. Example program selector                              :day1_2:

Visitors who don't know Lox currently have nothing to do. A dropdown of
curated samples is the single highest-impact demo fix.

** TODO Build the selector mechanism
- Small dropdown/select in or near the editor pane; swapping an example
  replaces the editor contents and triggers the existing Build path.
- Seeding from the post code block already exists; this generalizes it.
  Likely touches: editor panel component, =mountVisualizer= /
  =fromPage= config.
- Keep it dependency-free and dumb: an array of ={ label, source }=.
- Persist last-chosen example in =sessionStorage= only if trivial;
  otherwise skip.

** TODO Write the five samples
Each sample is one panel's highlight reel. Short enough to read at a
glance (roughly 5–15 lines each).

- [ ] *Recursion* — =fib= or similar. Star of the show: call frames
  stacking and unwinding in the Stack panel during playback.
- [ ] *Closure* — exercises upvalue capture; Stack panel's upvalue
  formatting gets used; bytecode shows closure ops.
- [ ] *Function with parameters* — must exercise *parameter tracing*
  (select a param in the AST → =OP_GET_LOCAL= / =OP_SET_LOCAL=
  highlighting). This is the wow feature; at least one default-ish
  sample must show it off.
- [ ] *Loop* — visible stack churn while scrubbing; good playback
  scrubber demo.
- [ ] *Syntax error* — makes error rendering look intentional. Console
  shows stderr; nothing else falls over.

** TODO Sanity-check each sample end to end
For each: build, click through lexer/AST/bytecode, scrub the trace,
confirm connector lines and highlights behave.

* TODO [#A] 2. Surface the trace cap in the UI                        :day2:

Currently =while (true) print 1;= silently truncates at 10,000 steps with
only a devtools console error — from the visitor's seat the tool just
stops. An HN commenter will find this within minutes.

- [ ] Visible banner/notice in the playback (or console) panel when the
  cap is hit: e.g. "Execution trace capped at 10,000 steps — program may
  not have terminated."
- [ ] Confirm the playback controls behave sanely at the cap (scrubber
  bounds, step counter reads =10000 / 10000=, no dead buttons).
- [ ] Keep the existing devtools error; the banner supplements it.

Half a day. Do not build "continue past the cap" — that's future
directions.
