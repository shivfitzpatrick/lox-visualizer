~app/src/index.ts~ becomes the Vite entry and mounts the Lox
visualizer into ~#viz-lox-container~ on ~/visualizers~.

The Python visualizer is *unpublished, not deleted* — it is work in
progress.  Its substance (~py-core~, ~py-data~, ~emitter.py~, fixtures,
tests) is untouched.  What goes is only its *mounting mechanism*: the
code-anchor bootstrap it shares with Lox.  ~PythonVisualizer~ converts
to the same container mount in the same pass, so both visualizers have
one bootstrap shape and the anchor API can be deleted outright.

Direction this is heading (not in scope here): the language tabs move
into the Vite app, and ~index.ts~ mounts both visualizers into their
containers.  Converting Python now is what makes that a small change
later.

* Background

Until now the ~<pre class="language-nil">~ block in
~content/visualizers.md~ did *two* jobs:

1. it was the *mount point* — ~mountVisualizer()~ replaced the ~<pre>~
   with the built layout root;
2. its text was the *initial editor document*.

The page has already been rewritten (uncommitted, in the working tree):
the language tabs, the Python section and both fenced code blocks are
gone, replaced by

: <script src="/app/index.js" type="module" data-code="#viz-lox .language-nil"></script>
: <div id="viz-lox-container"></div>

So the two jobs now split: the mount point is the empty ~div~, and the
initial document comes from the samples store added in ~02~.  Nothing
below changes the layout DOM, the stores, the panels or the connector
layer — only how the apps are bootstrapped.

This also finishes the bootstrap extraction that
~01-prereq-build-entry.org~ asked for: ~index.ts~ *is* the ~main.ts~
that doc wanted, so ~lox-visualizer.ts~ finally loses its self-boot
tail and becomes importable without mounting anything.

* Supersedes

~00-overview.org~ decision (2026-08-11): "the page-scraped initial doc
(fenced block in ~content/visualizers.md~) stays the initial editor
content".  There is no fenced block any more; the default sample *is*
the initial content, and ~DEFAULT_SAMPLE_LABEL~ inverts from "must
match the page" to "is whatever the store's first entry is".

/** Mount the layout DOM inside a page-provided container. */
export function mountVisualizerInto(container: HTMLElement, layout: VisualizerLayout) {
    const { root, containers } = buildLayoutDOM(layout);
    container.replaceChildren(root);   // idempotent if index.ts ever re-mounts
    return { root, containers };

* Outcome (2026-08-12)

Landed as planned, with two deviations:

- ~parseDataLayout~ *kept* (unused for now).  It is pure, tested, and
  the obvious parser for a ~data-layout~ attribute on the container div
  or on future tab config; only the DOM-script coupling was deleted.
- ~LoxVisualizer.sampleCode~ renamed to ~initialDoc~ so both
  visualizers name the field the same thing.

Verified: ~make typecheck~ clean; ~vite build~ emits ~app/dist/index.js~
(978 kB) plus the five lazy sample chunks and no ~python-visualizer~
output; the page rendered headless (chromium, static harness over
~app/dist~ + ~static/~) mounts ~.lox-visualizer~ inside
~#viz-lox-container~, opens on "Loop printer", compiles through WASM
(bytecode pane full of ~OP_*~) and reaches ~data-execution-active~ with
no console errors.

* Net effect

One ~6-line function in ~mount.ts~, two static factories reshaped
alike, a 12-line entry file — minus the code-anchor and script-attribute
machinery.  Python keeps every line that does compiler work and loses
only the bootstrap it was going to lose anyway.
