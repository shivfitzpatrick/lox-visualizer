#+title: Execution Mode
#+date: 2026-06-19
#+phase: 4 (after 04, 05, 06)

"Execution mode" is the concept that ties all playback-driven visuals together
under a single gate.  Currently the yellow arrow and connector draw whenever
=currentStep= is non-null; execution mode makes them conditional on the user
explicitly engaging the playback controls.

*Invariants:*
- Yellow border on playback panel ↔ execution mode is active.
- =bc-executing= row marker and =bc-exec → ast-exec= connector ↔ active.
- Clicking the playback panel or any control inside it → enters execution mode.
- Clicking anything else (other panel content, document background) → exits.
- Panning the AST (drag gesture) does NOT exit execution mode.
- In execution mode the AST viewport pans to the executing node without
  touching =selectionStore= (the pan is execution-driven, not user-selection-driven).

*Pan to the executing node in execution mode:*
When =active= becomes true (or step changes while active), we want the AST
viewport to pan so the highlighted node is visible.  We do NOT want this to
write =selectedStart= to =selectionStore=, because that would cause the bytecode
panel to add a =bc-selected= highlight on top of =bc-executing=.

Approach: add a boolean guard =skipNextHighlight= on =AstPanel=.  Set it before
calling =this.handle?.(srcOffset)= inside =applyExecHighlight=; the =onHighlight=
callback (in =onDataChange=) checks the guard and skips the =selectionStore.set=
write if it is true, then resets the flag.

#+begin_src typescript
// in onDataChange, inside the onHighlight callback:
(node, _el) => {
    if (this.skipNextHighlight) {
        this.skipNextHighlight = false;
        return;
    }
    // … existing selectionStore.set and setAnchor calls
},

// in applyExecHighlight, after adding 'ast-executing' class:
if (this.executionStore?.get().active && this.handle) {
    this.skipNextHighlight = true;
    this.handle(instr.srcOffset);   // pans viewport to the node
}
#+end_src

The guard prevents the pan from propagating into =selectionStore= and avoids the
double-highlight on the bytecode panel.

Also gate =refreshAnchor='s =ast-exec= publish on =active=:

const active = this.executionStore?.get().active ?? false;
