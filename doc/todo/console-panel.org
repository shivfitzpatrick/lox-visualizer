* Overview

Add a console panel below the AST that shows output from =print= statements and
runtime/compile errors from clox.

The C side already emits what we need:
- =printValue= emits ={"msg_type": "print", "text": "..."}= to stdout when
  =JSON_LOG_PRINT= is defined (it is, per the Makefile).
- =runtimeError= and compile errors go to =stderr=, which =lox-core.ts= already
  routes to a =stderr= d3 event.

No C changes are needed.

** Event flow reminder
- =lox-core.ts print()= receives a stdout line → if it starts with ={=, parses
  and dispatches to =events.call(event.msg_type, ...)=.
- =lox-core.ts printErr()= receives a stderr line → dispatches =stderr= event.
- =lox-visualizer-demo.ts= listens to d3 events and drives state + rendering.

** Render timing note
Unlike the lexer (triggered by TOKEN_EOF) and AST (triggered by PROGRAM_CLOSE),
errors can fire without either of those events (e.g. a compile error stops
before any tokens). The console render should fire unconditionally after every
=runSource()= call via =requestAnimationFrame=, in addition to being called from
the main =render()= path.

Several sub-changes in the demo component:

*** Replace the =print= console.log stub with state push

// before
lox.events.on('print', (event) => console.log('PRINT', event.text));

*** Add =displayConsole()= method
Renders =consoleMessages= into =#lox-console= using d3 (same pattern as
=displayLex=). Each message is a =<div>= with class =console-print= or
=console-error=.

*** Trigger console render unconditionally after each run
