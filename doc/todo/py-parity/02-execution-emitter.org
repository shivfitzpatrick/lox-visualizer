#+title: Execution Trace Emitter
#+date: 2026-06-19
#+phase: 1

Extend ~emitter.py~ to execute compiled code and emit a step trace compatible
with ~VmStep~ / ~TaggedPrint~.  See [[file:design.org][design.org]] § Execution parity.

* Dependencies

- Phase 0 optional but recommended (orchestrator hygiene).

* Tasks

** TODO Execute compiled code with sys.monitoring
   :PROPERTIES:
   :files: app/src/python-visualizer/emitter.py
   :END:

After ~compile()~, register ~sys.monitoring~ ~INSTRUCTION~ callback (Python
3.12+).  On each callback, append a step record:

#+begin_src python
{"msg_type": "vm_step", "chunk": qualname, "offset": off, "stack": [...], "frames": [...]}
#+end_src

Use ~dis.get_instructions~ to resolve chunk name.  Cap at ~MAX_STEPS = 10_000~.

** TODO Simulate evaluation stack

Maintain a list during the monitoring callback.  Apply per-opcode push/pop using
~dis.stack_effect~ (and opcode-specific value rules for ~LOAD_CONST~,
~LOAD_NAME~, etc.).  Map Python values to ~StackValue~ JSON (~t~, ~v~, ~name~).

Build ~frames~ from ~PY_START~ / ~PY_RETURN~ monitoring events (or trace
~call~ / ~return~).
