#+title: Python Visualizer — Lox Parity Overview
#+date: 2026-06-19

This directory breaks [[file:design.org][design.org]] into parallelizable work
streams.  Each numbered file is a self-contained sequence meant to be done in
order by one person or agent.  Files with the same phase number have no
inter-dependencies and can be worked *in parallel*.

* Goal end-state

The Python visualizer matches the Lox visualizer's recent improvements:

1. Live execution trace with step-by-step playback.
2. Stack panel (simulated evaluation stack), bytecode ► arrow, AST highlight.
3. Console prints synced to playback step.
4. Shared shell features (panel labels, responsive layout) working on Python posts.

* Phases and parallelism

** Phase 0 — Quick wins (no emitter changes)

Orchestrator-only; can land immediately.

- [[file:01-orchestrator-wiring.org][01-orchestrator-wiring.org]] — bc-exec connector, executionStore field, reset on run

** Phase 1 — Execution emitter (Python / Pyodide)

Single stream; all work in ~emitter.py~ and ~py-data.ts~ types.  Blocks Phase 2.

- [[file:02-execution-emitter.org][02-execution-emitter.org]] — sys.monitoring trace, stdout capture, stack simulation, JSON output

** Phase 2 — Orchestrator execution wiring (after Phase 1)

- [[file:03-execution-orchestrator.org][03-execution-orchestrator.org]] — populate ExecutionStore, console split, MAX_STEPS

** Phase 3 — Verification

- [[file:04-tests-polish.org][04-tests-polish.org]] — vitest, browser smoke, optional layout restore on pyvis post

** Phase 4 — Shared shell follow-ups

Nothing outstanding.  Responsive layout is handled entirely in
~static/css/lox-visualizer.css~ by wrapping flex rows, so
~python-visualizer.ts~ needs no viewport hook of its own — it inherits the
behavior by mounting the same DOM.
